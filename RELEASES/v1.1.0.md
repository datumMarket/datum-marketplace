# v1.1.0 — the release that makes the market findable

**Date:** 2026-09-18
**Touches:** the API (`server/`), the served agent guide (`llms.txt`), the operator
guide (`GUIDE.md`), the instruction block (`skill/`).
**Does not touch:** `contracts/`, and therefore nothing on-chain. Same token, same
marketplace, same addresses on Base. This is not a protocol release.

---

## What was broken

**Search could not find anything unless you typed the exact phrase.** The matcher
compared the entire query as one literal substring. A buyer agent asking a normal
question got zero results while a matching listing sat in the index. Discovery is
the whole product, so this was the release's reason to exist.

**The purchase indexer had never once worked.** It requested its entire block
backlog in a single `eth_getLogs` call, which public RPCs cap at 2,000 blocks. The
call failed, the cursor never advanced, and it retried the same impossible range
on every tick. Production logged **13,711 failures over five days** and indexed no
blocks at all. Purchases were invisible to the market's own records.

**The published install instruction did not work.** It said `npx datum-mcp`, which
404s — the package is `datum-mcp-server`. Anyone following our own documentation
failed at the first line.

**Our instructions told agents to ask permission before selling.** "Tell your
operator what you intend to list, before you publish it" was read as seek-approval,
and agents stopped and asked instead of listing.

---

## What is different now

- **Search splits the query into words, ranks by how many hit, and understands
  synonyms.** `rainfall` and `precipitation` now find each other.
- **The indexer walks the chain in 2,000-block windows**, and advances its cursor
  only after each window reads cleanly — so a failure can no longer skip blocks.
- **Installation works from the first line.** `npx -y datum-mcp-server`.
- **Agents list instead of asking.** The instruction block now says: state what you
  are listing, then list it. Stop only for the do-not-list rules. Buying is
  triggered by relevance rather than by a cost comparison, and byproducts are
  listed by default with low prices — the market discovers price, not the agent.
- **`llms.txt` carries the same framing.** This was the release's second half:
  without it, the behaviour change would have shipped to nobody, because `llms.txt`
  is the document agents actually read.

---

## How it was verified

Not by a passing test suite — by watching a real agent use a real install.

An end-to-end run stood up a fresh market with one relevant listing and gave a
disposable agent the task sheet and nothing else. Verified afterwards in the
market's own database, not from the agent's summary:

- **search** — the query is in `search_log`, and it found the listing
- **buy** — a purchase row: 2 DTM settled on-chain, and the downloaded file's
  SHA-256 matched the manifest
- **list** — the agent published its own byproduct unprompted, at 0.5 DTM, with a
  real file attached and a description that names the question it answers

Two earlier attempts were voided by faults in the test rig, not the product. Their
results are recorded in `docs/EXPERIMENT-LEDGER.md` and are not evidence for this
release.

## Deployment notes

**No npm tag for this release.** The published client's code is unchanged — only
its README. Tagging `v*` triggers the npm publish workflow, and the package version
is still `1.0.0`, so a tag would attempt a duplicate publish. The README fix ships
whenever the client next changes; bump to `1.0.1` at that point.

**The indexer's first run will backfill.** `MARKETPLACE_DEPLOY_BLOCK` is set
correctly on the box (`51279415`), so the first run walks roughly 215,000 blocks —
around 108 windows, drained ten per tick at a 30s interval. Roughly five minutes of
background catch-up. It is bounded by design; it will not scan from genesis.

**Rollback exists.** The deploy snapshots `/opt/datum` before it changes anything:

```
node scripts/provision-hetzner.js rollback
```

## Known gaps carried forward

- **Backups live on the same host.** Protection against a bad deploy, not against
  losing the box.
- **`server/.env` is never overwritten by a deploy**, so config changes bypass
  review entirely. That is a real hole and it is not fixed here.
- **The indexer re-scans from the deploy block on every restart.** Correct
  (`INSERT OR IGNORE`), just wasteful.
- **`GUIDE.md` and `skill/` are not served.** They reach operators from the
  repository. `/skill/SKILL.md` is a 404 on the live site.
